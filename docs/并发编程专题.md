## 一 Send 和 Sync
### 1.1 什么是Send
* Send表示值或者所有权可以在线程之间安全传递
* 只有实现了Send的数据结构或者类型才可以在线程之间安全传递
* 几乎所有基本类型，比如i32、f64、String等都自动实现了 Send
* 不安全类型如原始指针(*const T、*mut T)默认不实现Send，因为它们的访问没有保证线程安全

### 1.2 什么是Sync
* Sync表示值或者所有权可以在线程之间安全共享
* 只有实现了Sync，才可以安全地在多线程中使用其共享引用(&T)
* Rust中的 &T 是只读的，因此在多个线程中共享 &T 是线程安全的
* 基本类型如i32、f64 等以及线程安全类型如Arc<T>、Mutex<T>默认实现了 Sync
* 原始指针(*const T、*mut T)默认不实现 Sync，因为它们的引用可能不是线程安全的

### 1.3 Send 和 Sync比较
**作用**  
- Send: 类型值可以在线程之间移动
- Sync: 类型的引用可以在多个线程中共享

**关键点**  
- Send: 表示所有权的传递是线程安全的
- Sync: 表示共享引用的访问是线程安全的

**实现场景**  
- Send: 适用于跨线程传递数据的场景
- Sync: 适用于跨线程共享数据的场景

**自动实现**  
- Send: 基本类型默认实现
- Sync: 基本类型默认实现


## 二 线程并发编程模型
### 2.1 普通线程
Rust 提供了原生线程支持，通过标准库的 std::thread 模块可以轻松创建线程并实现并发任务  
* 特点：低级模型，直接控制线程的创建和管理
* 适用场景：需要高灵活性或对线程生命周期有特殊需求的场景
```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        println!("Hello from a thread!");
    });

    handle.join().unwrap();
    println!("Main thread done!");
}
```

### 2.2 消息传递(Channel)
通过 std::sync::mpsc 提供的单生产者、多消费者（multi-producer, single-consumer）通道，实现线程间的数据传递  
* 特点：线程之间无共享内存，通过消息传递避免数据竞争
* 适用场景：需要线程安全的数据传递和任务分发
```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        tx.send("Hello from another thread!").unwrap();
    });

    let received = rx.recv().unwrap();
    println!("Received: {}", received);
}
```

### 2.3 共享状态或者互斥锁(Mutex\RxLock)
通过 std::sync 提供的同步原语（如 Mutex 和 RwLock）在多个线程之间共享状态  
* 特点：共享内存的线程模型，显式控制数据访问
* 适用场景：需要共享可变数据的场景
```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            let mut num = counter.lock().unwrap();
            *num += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("Result: {}", *counter.lock().unwrap());
}
```

### 2.4 异步编程(Async/Await)
Rust 提供了 async/await 语法以及相关运行时（如 Tokio 和 async-std）实现高效的异步编程  
* 特点：基于任务的并发模型，单线程或多线程事件驱动
* 适用场景：I/O 密集型任务、高并发场景
```rust
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    let task1 = async {
        sleep(Duration::from_secs(1)).await;
        println!("Task 1 done!");
    };

    let task2 = async {
        sleep(Duration::from_secs(2)).await;
        println!("Task 2 done!");
    };

    tokio::join!(task1, task2);
}
```

### 2.5 线程池
Rust 提供了高性能的并行库 Rayon，支持工作窃取线程池，实现任务并行化  
* 特点：线程池自动管理任务，用户只需关注逻辑
* 适用场景：数据并行计算、大量相同类型任务
```rust
use rayon::prelude::*;

fn main() {
    let nums: Vec<i32> = (1..=10).collect();
    let sum: i32 = nums.par_iter().sum();
    println!("Sum: {}", sum);
}

```

### 2.6 Actor线程模型
Actor 模型通过将状态和行为封装在单一实体（Actor）中，避免了共享内存  
* 特点：避免显式同步，通过消息传递管理 Actor 状态
* 适用场景：分布式系统、高并发场景
```rust
use actix::prelude::*;

struct MyActor;

impl Actor for MyActor {
    type Context = Context<Self>;
}

struct MyMessage;

impl Message for MyMessage {
    type Result = &'static str;
}

impl Handler<MyMessage> for MyActor {
    type Result = &'static str;

    fn handle(&mut self, _msg: MyMessage, _ctx: &mut Context<Self>) -> Self::Result {
        "Hello from MyActor"
    }
}

#[actix_rt::main]
async fn main() {
    let addr = MyActor.start();
    let res = addr.send(MyMessage).await.unwrap();
    println!("{}", res);
}
```
